# Диагностика keep-alive → echo

## Механизм

```
Клиент                          Сервер
  │                               │
  │  Encrypt([]byte{})            │
  │  ─── [HMAC(4)][DynID(2)] ──► │  Decrypt → len=0 → keep-alive
  │     [Nonce(12)][AES-GCM]     │  Encrypt({0x01})
  │  ◄── [HMAC(4)][DynID(2)] ─── │  WritePacket (через peer.Writer)
  │     [Nonce(12)][AES-GCM]     │
  │                               │
  │  Decrypt → {0x01} → echo!    │
```

## Принципиальные требования

1. **UDP должен доходить** до сервера. Если провайдер или ТСПУ блокирует UDP — echo не вернётся никогда (и протокол не работает).
2. **Ключи совпадают** — `DeriveKey(secret)` даёт одинаковый `[32]byte` на клиенте и сервере.
3. **ShortID совпадает** — клиент использует свой ID, сервер находит пира по shortID.
4. **RoutingSalt совпадает** — используется в DynamicID.

## Как проверять

### 1. Доходит ли UDP вообще?
На сервере:
```bash
tcpdump -i any -n 'udp and host <CLIENT_IP>'
```
На клиенте:
```go
go run ./cmd/echotest/
```

### 2. Есть ли пир с таким shortID?
Серверный лог: `[КEEP-ALIVE] ShortID=N` — появляется при каждом пустом пакете.
Если нет — пакет не дошёл или HMAC не совпал.

### 3. Ошибки шифрования?
Серверный лог: `[DROP] ... shortID=0 replay=N HMAC=N decrypt=N`
- `shortID=N` — пакет дошёл, но пир с таким ID не найден
- `replay=N` — bloom filter отбросил (повтор nonce или ложное срабатывание)
- `HMAC=N` — маркер не совпал (не тот ключ)
- `decrypt=N` — AES-GCM не расшифровался

### 4. Ошибки записи echo?
Серверный лог: `[ОШИБКА] echo encrypt: ...` или `[ОШИБКА] echo write: ...`

## Найденная проблема (май 2026)

UDP-пакеты от клиента (77.106.118.52, РФ) до сервера (45.134.39.18, EU) **не доходят**.
Провайдер/ТСПУ блокирует UDP на всех портах. TCP (ping, SSH, WS) работает.

**Протокол Hasta-Vaquet не содержит бага.** Keep-alive → echo цикл корректен.
Проблема на сетевом уровне: без UDP протокол не может установить соединение.

## Решения

1. **WS (WebSocket)** — единственный рабочий транспорт из текущей локации.
   Использует TCP, проходит через DPI. Скорость ~150-265 Mbps.

2. **Xray Reality** — отдельный сервис на :443. TLS к microsoft.com.
   Не зависит от Hasta-Vaquet.

3. **Изменить провайдера/локацию** — если UDP нужен, подключаться через
   сеть где не блокируют UDP (например, мобильный оператор, другая страна).

4. **TUN через WS** — после установки WS-соединения весь трафик идёт
   через зашифрованный канал. UDP-пакеты внутри туннеля не зависят от
   внешнего UDP-блокирования.

## Тестовая инфраструктура

- `cmd/echotest/` — диагностика echo-цикла (UDP, QUIC, WS)
- `cmd/bench/` — замеры пропускной способности (все транспорты)
- При UDP-блокировке бенч автоматически переключается на WS

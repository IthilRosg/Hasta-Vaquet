# Network & Crypto Standards

- **Шифрование:** Только AES-256-GCM. 
- **Ключ:** Генерируется строго как `sha256.Sum256([]byte(secret))`.
- **MTU:** Строго 1300 байт. Это компенсирует 28 байт оверхеда GCM и предотвращает фрагментацию.
- **Keep-Alive маркер:** Пакет с зашифрованным payload нулевой длины (`encrypt([]byte{})`) — служебный сигнал Keep-Alive. Сервер не направляет его в TUN, только логирует. Интервал отправки клиентом: случайный 10-30 секунд.
- **Внутренний формат payload (Phase 5):**
  ```
  [2 байта real_len uint16] [real_data] [random_padding]
  ```
  Получатель читает первые 2 байта как длину реальных данных, остальное отбрасывает как padding.
- **Обработка пакетов:**
    - Обрабатывать ТОЛЬКО IPv4 (`packet[0]>>4 == 4`).
    - Игнорировать IPv6 и мусорный трафик.
    - Серверный буфер: `make([]byte, 65535)`.

## Phase 5: Stateless Polymorphic Obfuscation

- **Абсолютный Stateless:** Вся вариативность трафика извлекается из 12-байтового Nonce AES-GCM пакета. Никакого серверного состояния между пакетами.
- **QUIC Header Mask (Critical):** Первый байт HMAC-маркера на проводе всегда имеет бит 6 = 1 (`marker[0] |= 0x40`). При HMAC-проверке получатель снимает бит 6 с ОБОИХ аргументов (`marker[0] &^= 0x40` И `expected[0] &^= 0x40`). Без этого ~50% пакетов падают с HMAC mismatch.
- **Анти-сканер маркер:** Каждый UDP-пакет начинается с `HMAC-SHA256(SecretKey, Nonce)[:4]`. Сервер проверяет маркер ДО дешифрации. При несовпадении — молчаливый Drop (черная дыра, no response).
- **Асимметричный паддинг (Nonce-ротация):**
  - **Клиент:** Всегда лёгкий профиль — 0-40 байт случайного padding.
  - **Сервер:** Выбор профиля по `int(Nonce[0]) % 2`:
    - `0` — **Medium**: padding 50-150 байт
    - `1` — **Chaos**: заполнение до ~1280 байт inner payload
  - Padding заполняется `crypto/rand`
- **Wire Format пакета (Phase 5):**
    ```
    [HMAC-SHA256(Key, Nonce)[:4] | QUIC_bit] [Nonce 12 байт] [AES-GCM(inner)]
    ```
    где `inner` = `[2 байта real_len] [real_data] [random_padding]`
- **Запрет Epoch-based ротации:** Категорически не используем профили, привязанные ко времени (рассинхрон часов клиент/сервер, предсказуемая сигнатура по временным окнам).

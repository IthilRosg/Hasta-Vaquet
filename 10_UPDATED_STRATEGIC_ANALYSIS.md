## 2. Критические баги и проблемы в коде

### 2.1 Три копии криптографии (КРИТИЧЕСКИЙ)

**Файлы:**
- `main.go:34-122` — standalone `encrypt()`, `decrypt()`, `fnv1a16()`
- `core/crypto.go:24-109` — библиотечные `Encrypt()`, `Decrypt()`, `fnv1a16()`
- `server/server.go:100-204` — серверные `encrypt()`, `decrypt()`, `fnv1a16()`

**Проблемы:**
1. `main.go` использует `math/rand` для паддинга (строка 50) — **предсказуемый паддинг**, DPI может детектировать
2. `core/crypto.go` тоже использует `math/rand` для паддинга (строка 31) — **та же проблема**
3. `server/server.go` использует `math/rand` для паддинга (строки 113, 118) — **та же проблема**
4. Серверный `fnv1a16` (строка 64-66) вызывает `fnv1a(data, 0)` с seed=0, а клиентский `fnv1a16` (core/crypto.go:15) — без seed. **Результат одинаковый, но это риск** — если кто-то изменит один, не изменит другой.
5. `main.go` НЕ имеет: statsLoop, RTT-замера, обработки echo `0x01`, нормальных колбеков
6. Любое изменение протокола = правка 3 файлов

### 2.2 Отсутствие Kill Switch (ВЫСОКИЙ)

**Ни на одной платформе нет Kill Switch.** При обрыве VPN-соединения:
- Windows: весь трафик идёт напрямую через реальный IP
- Android: весь трафик идёт напрямую
- Пользователь не знает, что слил реальный IP

### 2.3 Отсутствие Auto-Reconnect (ВЫСОКИЙ)

**Ни на одной платформе нет авто-переподключения.** При обрыве:
- Пользователь должен вручную переподключиться
- Нет экспоненциального backoff
- Нет UI-индикации "Reconnecting..."

### 2.4 `math/rand` вместо `crypto/rand` для паддинга (ВЫСОКИЙ)

**Все 3 файла используют `math/rand`** для генерации размера паддинга:
- `main.go:50` — `mathrand.Intn(41)`
- `core/crypto.go:31` — `mathrand.Intn(41)`
- `server/server.go:113,118` — `mathrand.Intn(101)`, `mathrand.Intn(...)`

**Почему это плохо:** `math/rand` по умолчанию seed'ится временем. Если DPI знает примерное время отправки пакета, он может предсказать размер паддинга и использовать это как сигнатуру.

**Решение:** Заменить на `crypto/rand` для генерации размера паддинга.

### 2.5 Android: `androidListener` — заглушка (СРЕДНИЙ)

`core/gomobile.go:103-116` — `androidListener.OnStatus()` пустой. Статистика не передаётся в Kotlin UI.

### 2.6 Android: нет Smart Bypass (СРЕДНИЙ)

`07_CURRENT_PHASE.md` упоминает `addDisallowedApplication`, но в реальном коде Android-клиента он не реализован. Банки будут блокировать VPN.

### 2.7 Сервер: нет rate limiting (ВЫСОКИЙ)

`server/server.go` — нет лимита пакетов/сек на IP. Любой может отправить UDP flood и забить сервер.

### 2.8 Сервер: нет forward secrecy (СРЕДНИЙ)

Ключи статические. Если ключ скомпрометирован — весь прошлый трафик можно расшифровать.

### 2.9 `main.go` route cleanup hardcoded (НИЗКИЙ)

`main.go:235` — `route delete 0.0.0.0 10.0.0.1` захардкожен. Должен использовать `cfg.InternalIP`.

### 2.10 Сервер: `encrypt` для echo игнорирует ошибку (НИЗКИЙ)

`server/server.go:447` — `enc, _ := encrypt(...)` — ошибка игнорируется.

## 3. Ситуация в РФ (Май 2026)

### Что происходит:

1. **РКН активно блокирует VPN-протоколы** — OpenVPN, WireGuard, Shadowsocks детектируются по DPI
   - Наш кастомный протокол — **реальное преимущество**, но нужно полевое тестирование

2. **Банки (Сбер, ВТБ, Тинькофф, Альфа) блокируют VPN** — через Android API `IS_VPN` / `TRANSPORT_VPN`
   - Без Smart Bypass (`addDisallowedApplication`) пользователь не зайдёт в банк
   - Это **критично для adoption** — люди не будут использовать VPN, который ломает банк

3. **Госуслуги и МФЦ работают только с российским IP** — нужен split tunneling / bypass

4. **YouTube заблокирован** (с конца 2025) — VPN нужен ежедневно для миллионов

5. **Telegram периодически троттлится** — тоже причина использовать VPN

6. **Альтернативы:**
   - Amnezia VPN — бесплатная, но DPI-устойчивость средняя, нет bypass банков
   - Outline — Shadowsocks блокируется РКН
   - ByeDpi / GoodbyDPI — работают только для HTTP, не для всего трафика
   - Самописные решения — ниша открыта

### Вывод по рынку:

**Наше уникальное предложение:** кастомный протокол (DPI не видит) + Smart Bypass (банки работают).

Но пока bypass не реализован — мы ничем не лучше Amnezia для обычного пользователя.

**Android — приоритет #1** (70%+ рынка смартфонов в РФ).

**iOS можно отложить** — дорого ($99/год), сложно (Apple review), маленькая доля.

## 5. Корневые причины тупика (обновлённый анализ)

1. **Paralysis by analysis** — план на 15 фаз, а база не доделана
2. **Три копии криптографии** — любой фикс = 3 правки, нет тестов
3. **Нет реальных пользователей** — протокол не тестировался против реального DPI
4. **Нет CI/CD** — каждый билд ручной
5. **Android на 70%** — нет kill switch, reconnect, статистики, bypass
6. **Распыление фокуса** — вместо "сделать Windows идеально" планируем macOS, iOS, Linux GUI

## 11. Резюме

**Проект не в тупике. Проект на правильном пути, но с неправильным фокусом.**

### Сильные стороны:
- Свой крипто-протокол с реальной DPI-устойчивостью (это редкость)
- Работающий Windows GUI
- Работающий сервер с веб-панелью
- Архитектура готова к расширению (build tags, interface-based API)
- Deploy на реальном VPS с TLS

### Слабые стороны:
- Три копии кода криптографии
- Нет kill switch — пользователь сливает IP
- Нет auto-reconnect — рвётся и всё
- Android не доделан (а это главная платформа для РФ)
- Нет реальных пользователей = нет обратной связи
- План на 15 фаз при готовности 3
- `math/rand` для паддинга — предсказуемо для DPI

### Что делать ПРЯМО СЕЙЧАС:

1. **Консолидировать код** (Приоритет 0) — 1-2 дня
2. **Kill Switch + Auto-Reconnect** (Приоритет 1) — 2-3 дня
3. **Добить Android** (Приоритет 2) — 2-3 дня
4. **Найти 5-10 тестеров в РФ** (Приоритет 3) — немедленно
5. **Итерировать по фидбеку**

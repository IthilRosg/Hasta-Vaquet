## 2. КРИТИЧЕСКИЕ БАГИ И ПРОБЛЕМЫ В КОДЕ

### 2.1 Три копии криптографии (КРИТИЧЕСКИЙ)

**Файлы с дублированием:**
- `main.go:34-122` — standalone `encrypt()`, `decrypt()`, `fnv1a16()` — НЕ использует core/
- `core/crypto.go:24-109` — библиотечные `Encrypt()`, `Decrypt()`, `fnv1a16()`
- `server/server.go:100-204` — серверные `encrypt()`, `decrypt()`, `fnv1a16()` — НЕ использует core/

**Последствия:**
- Любое изменение протокола = правка 3 файлов
- `main.go` НЕ ИМЕЕТ: statsLoop, RTT-замера, обработки echo 0x01
- Тесты криптографии невозможно написать один раз
- Баг в одном месте не фиксируется в других

### 2.2 `math/rand` вместо `crypto/rand` для паддинга (ВЫСОКИЙ)

**Где:**
- `main.go:50` — `mathrand.Intn(41)`
- `core/crypto.go:31` — `mathrand.Intn(41)`
- `server/server.go:113,118` — `mathrand.Intn(101)`, `mathrand.Intn(...)`

**Почему это плохо:** `math/rand` seed'ится временем. DPI зная примерное время отправки может предсказать размер паддинга и использовать как сигнатуру.

**Важное замечание:** Серверный паддинг использует `nonce[0] % 2` для выбора профиля (Medium/Chaos) — это детерминировано из nonce, но сам размер паддинга внутри профиля — `math/rand`.

### 2.3 Отсутствие Kill Switch (КРИТИЧЕСКИЙ)

**Ни на одной платформе нет Kill Switch.** При обрыве:
- Windows: весь трафик идёт напрямую через реальный IP
- Android: весь трафик идёт напрямую
- Пользователь не знает, что слил реальный IP

### 2.4 Отсутствие Auto-Reconnect (ВЫСОКИЙ)

**Ни на одной платформе нет авто-переподключения.** При обрыве пользователь должен вручную переподключиться. Нет экспоненциального backoff.

### 2.5 Android: `androidListener` — заглушка (СРЕДНИЙ)

`core/gomobile.go:107-115` — `OnStatus()` пустой. Статистика не передаётся в Kotlin UI. `GetStats()` работает через poll, но listener не используется.

### 2.6 Android: нет Smart Bypass (ВЫСОКИЙ)

В коде Android-клиента `addDisallowedApplication` не реализован. Банки (Сбер, ВТБ, Тинькофф) будут блокировать VPN.

### 2.7 Сервер: нет rate limiting (ВЫСОКИЙ)

`server/server.go` — нет лимита пакетов/сек на IP. Любой может отправить UDP flood.

### 2.8 Сервер: `encrypt` для echo игнорирует ошибку (НИЗКИЙ)

`server/server.go:447` — `enc, _ := encrypt([]byte{0x01}, peer.Key[:], peer.ShortID)` — ошибка игнорируется.

### 2.9 `main.go` route cleanup hardcoded (НИЗКИЙ)

`main.go:235` — `route delete 0.0.0.0 10.0.0.1` захардкожен. Должен использовать `cfg.InternalIP`.

### 2.10 Сервер: `fnv1a` с seed=0 vs клиентский без seed (РИСК)

`server/server.go:64-66` — `fnv1a(data, 0)` вызывает с seed=0.
`core/crypto.go:15` — `fnv1a16(data)` без seed.

Результат одинаковый (seed=0 XOR constant = constant), но если кто-то изменит один — сломается совместимость.

### 2.11 Сервер: нет forward secrecy (СРЕДНИЙ)

Ключи статические. Если ключ скомпрометирован — весь прошлый трафик можно расшифровать.

### 2.12 `core/crypto.go` — `Decrypt` не использует DynamicID для lookup

`core/crypto.go:78` — `copy(authData[:2], packet[4:6])` — берёт DynamicID из пакета, но это правильно для клиента (он знает свой ShortID). Проблема только если клиент получит пакет другого клиента — но это маловероятно при правильной маршрутизации.

## 3. СИТУАЦИЯ В РФ (МАЙ 2026)

### Что происходит:

1. **РКН активно блокирует VPN-протоколы** — OpenVPN, WireGuard, Shadowsocks детектируются по DPI
   - Наш кастомный протокол — реальное преимущество, но нужно полевое тестирование

2. **Банки (Сбер, ВТБ, Тинькофф, Альфа) блокируют VPN** — через Android API `IS_VPN` / `TRANSPORT_VPN`
   - Без Smart Bypass (`addDisallowedApplication`) пользователь не зайдёт в банк
   - Это критично для adoption — люди не будут использовать VPN, который ломает банк

3. **Госуслуги и МФЦ работают только с российским IP** — нужен split tunneling / bypass

4. **YouTube заблокирован** (с конца 2025) — VPN нужен ежедневно для миллионов

5. **Telegram периодически троттлится** — тоже причина использовать VPN

6. **Альтернативы:**
   - Amnezia VPN — бесплатная, DPI-устойчивость средняя, нет bypass банков
   - Outline — Shadowsocks блокируется РКН
   - ByeDpi / GoodbyDPI — работают только для HTTP
   - Самописные решения — ниша открыта

### Вывод по рынку:

**Наше уникальное предложение:** кастомный протокол (DPI не видит) + Smart Bypass (банки работают).

Но пока bypass не реализован — мы ничем не лучше Amnezia для обычного пользователя.

**Android — приоритет #1** (70%+ рынка смартфонов в РФ).

## 4. АНАЛИЗ vpn_detection.md (методика обнаружения VPN)

Этот документ описывает КАК банки и сервисы детектят VPN. Ключевые выводы:

### Прямые признаки (100% детект):
- Android: `IS_VPN` флаг, `TRANSPORT_VPN` в `NetworkCapabilities`
- iOS: системные VPN-конфигурации

### Косвенные признаки (уточняющие):
- Имена интерфейсов: `tun0`, `tun1`, `wg0`
- Нестандартный MTU (1300 vs 1500)
- Аномалии маршрутизации
- Изменённые DNS

### Что это значит для нас:

**На Android:** Единственный рабочий способ — `addDisallowedApplication()`. Это создаёт отдельный сетевой контекст для приложения, полностью минуя VPN. Сбер вызывает `hasTransport(TRANSPORT_VPN)` — получает `false`.

**На Windows/Linux:** IP/CIDR-маршруты работают, т.к. десктопные приложения проверяют серверную сторону (GeoIP), а не клиентские API.

**Split tunneling создаёт аномалии в таблицах маршрутизации** (раздел 7.6 vpn_detection.md) — это косвенный признак VPN. Но для РФ-пользователей это необходимый компромисс.

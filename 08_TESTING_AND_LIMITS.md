# Testing, Timeouts, and Fail-Safes

- **Правило 3-х попыток (Anti-Loop):**
  - Если ты пытаешься исправить ошибку компиляции или баг, и после 3-х попыток код всё ещё не работает — СТОП. 
  - КАТЕГОРИЧЕСКИ ЗАПРЕЩАЕТСЯ продолжать попытки. Остановись, опиши проблему пользователю, покажи логи и жди инструкций.

- **Pre-flight Checks (Обязательные проверки перед деплоем):**
  - Никогда не заявляй, что фича готова, не проверив её.
  - Перед загрузкой кода на сервер (VPS) всегда локально выполняй `go build`, чтобы исключить синтаксические ошибки.
  - При изменении криптографии (AES) обязательно прогоняй локальный тест зашифровки/расшифровки строки.

- **Сетевые Таймауты (Защита от зависаний):**
  - Любое сетевое взаимодействие в Go должно использовать контексты с таймаутом (`context.WithTimeout`). 
  - Бесконечное ожидание (`Dial`, `Read`, `Write` без дедлайнов) в критических узлах ЗАПРЕЩЕНО. 
  - На этапе тестирования туннеля (ping) всегда ограничивай время ожидания (например, `ping -c 4 -w 5 10.0.0.2` на Linux).
  - Keep-Alive отправляется клиентом каждые 10-30 секунд (random jitter). Если сервер не получает пакетов > 60 секунд — клиент скорее всего отвалился по NAT-таймауту.
- **Логирование:**
  - Попакетное логирование ЗАПРЕЩЕНО (генерирует десятки тысяч строк в минуту).
  - Агрегированная статистика выводится раз в 30 секунд (общее кол-во байт в обе стороны).
  - Keep-Alive пакеты логируются отдельно как `[KEEP-ALIVE] получено`, не смешиваясь со статистикой.
  - Клиент пишет `client.log` в свою директорию. Ключевые события: статус соединения, keep-alive отправлен, ошибки дешифрации.
- **Ошибки в крипто-путях (запрет):**
  - `aes.NewCipher`, `cipher.NewGCM`, `gcm.Open`, `gcm.Seal` — все возвращают `error`. Проглатывать эти ошибки через `_` КАТЕГОРИЧеСКИ ЗАПРЕЩЕНО.
  - Правильный паттерн: `block, err := aes.NewCipher(key); if err != nil { return nil, fmt.Errorf("context: %w", err) }`
  - Симптом: если `NewCipher` падает (невалидная длина ключа), а ошибка проглочена, `NewGCM` получает `nil` block — panic в рантайм.

- **HMAC / QUIC mask:**
  - 50% HMAC-mismatch на входящих пакетах = проблема QUIC-маски (бит 6). Проверить: `got & 0x40 == exp & 0x40` на первом байте marker.
  - Если все пакеты сыпят HMAC mismatch, но keep-alive проходит — ключи совпадают, проблема в маскировании бита 6.
  - **Правильно:** снимать бит 6 с marker И expected перед `hmac.Equal`: `marker[0] &^= 0x40; expected[0] &^= 0x40`
- **Echo Ping (Native UDP Echo):**
  - Keep-Alive клиента → сервер отвечает 1-байтовым зашифрованным пакетом (marker 0x01)
  - RTT = time.Now().UnixMilli() - lastKeepAliveTx
  - Loss = (echoSent - echoAcked) * 100 / echoSent
  - Отображается только после первого успешного эха. До этого — "—"
  - Нет зависимости от TCP, ICMP, DNS, внешних серверов
- **IPv6 Blackhole:** Маршрут `::/0` через Wintun (netsh interface ipv6 add route). IPv6 трафик падает, утечки нет. Проверка: `ping -6 8.8.8.8` должен выдавать "Destination unreachable".

- **Изоляция сбоев (Graceful Degradation):**
  - Падение одной горутины не должно "ронять" весь VPN-клиент. Используй обработку паник (`recover()`) в горутинах, которые читают/пишут в интерфейс Wintun.
